# FileSync

轻量级、中心化、手动触发的跨平台文件同步工具。仅依赖 Go 标准库，单一二进制，
无数据库、无自动同步、无鉴权、无版本管理。

- 第一阶段：HTTP 文件服务端 + CLI（serve / put / get / ls）
- 第二阶段：手动双向同步（init / sync），基于三方比较的变化检测与冲突处理

## 构建

```
go build -o filesync.exe .
# Linux:
GOOS=linux GOARCH=amd64 go build -o filesync .
```

## 快速开始

终端 1（服务端）：

```
./filesync serve --addr 127.0.0.1:8080 --data-dir data
```

终端 2/3（任意多个客户端，各自独立目录）：

```
./filesync init --server http://127.0.0.1:8080 D:/notes   # 初始化同步目录
cd /d/notes
./filesync sync                 # 双向同步整个目录
./filesync sync docs            # 只同步子目录
./filesync sync docs/a.md       # 只同步单个文件
./filesync sync --keep local    # 冲突自动保留本地版本
./filesync sync --keep remote   # 冲突自动保留远端版本
./filesync ls                   # 查看服务端文件
./filesync put report.pdf docs/report.pdf   # 手工上传（独立于同步状态）
./filesync get docs/report.pdf              # 手工下载
```

## 数据目录

服务端 `--data-dir` 缺省为运行目录下的 `./data`（自动创建）；所有文件按客户端
提供的相对路径（`/` 分隔）存储在该目录内，保留目录结构。客户端同步配置与基线
保存在同步目录下的 `.filesync.json`。

## 同步原理

每个客户端维护基线：记录每个文件"上次同步成功时两端共同内容"的 SHA-256。
每次 `sync` 对每个文件做三方比较（本地 / 服务器 / 基线）：

| 本地 | 服务器 | 结论 |
|------|--------|------|
| 未变 | 未变 | 跳过 |
| 已变 | 未变 | 上传（携带 `if-match=基线` 条件覆盖） |
| 未变 | 已变 | 下载 |
| 已变 | 已变（内容相同） | 记录基线，不传输 |
| 已变 | 已变（内容不同） | **冲突**：询问保留本地 / 远端 / 跳过 |
| 新文件 | — | 上传 |
| — | 新文件 | 下载 |
| 一端删除 | 保留 | 不传播删除，仅提示（两端都删则清理记录） |

- 无基线的首次同步遇两端同名但内容不同 → 同样按冲突处理，由用户选择版本。
- 上传携带 `if-match`：若服务器内容已被其他端并发修改，服务端拒绝（HTTP 412），
  客户端按冲突跳过并报告，绝不静默覆盖。
- 状态文件在文件传输过程中分批原子落盘（临时文件 + fsync + 改名）；同步被中断后
  重新 `sync` 会自动收敛（已完成的不重传，未完成的继续）。
- 冲突交互：终端内逐个询问 `[L]本地 / [R]远端 / [S]跳过`；`--keep` 可自动决策；
  stdin 关闭（脚本/管道）时冲突一律跳过并报告，退出码 1。

## HTTP API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/api/ping` | 健康检查 |
| GET  | `/api/ls?prefix=` | 文件列表（path / size / sha256 / mod_time） |
| GET  | `/api/get?path=` | 下载文件，响应头 `X-Checksum-SHA256` |
| PUT  | `/api/put?path=&overwrite=&if-match=` | 上传；新文件 201，已存在 409，条件覆盖不符 412 |

## 可靠性与安全设计

1. **路径校验**：拒绝绝对路径、`..`、`.`、反斜杠、盘符/冒号（含 NTFS ADS）、控制字符、
   Windows 保留名（CON/NUL/COM1…）、以 `.` 或空格结尾的段；服务端再做一次
   "不越出根目录"的二次确认。
2. **完整性**：所有传输强制 SHA-256 双向校验；长度不符或校验失败一律丢弃。
3. **原子写入**：上传/下载先写临时文件（fsync）再原子改名，中断不损坏已有文件。
4. **默认不覆盖**：`put` 遇同名返回 409；条件覆盖（`if-match`）防止并发修改被静默覆盖。
5. **100-continue**：上传被拒时客户端不发送文件体。

## 已知限制（后续阶段计划）

- 无鉴权，仅适用于本机或可信局域网
- 变化检测基于内容哈希：每次 sync 需读取两端全部文件（个人文档场景可接受）
- 不上传空目录；不保留/同步文件修改时间
- 删除不传播：需手动处理两端分歧（无 rm 命令）
- 不做分块/断点续传；并发同步同一服务器未加锁
- 数据目录内手工放置的符号链接可能指向外部（工具本身不会创建链接）
